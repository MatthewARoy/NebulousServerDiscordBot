# Plan: split runbot.py into cogs (review item #23)

Self-contained plan for a fresh agent session. Read `CLAUDE.md` first, then
this. The bot is **stable in production (v2.4.1)** — this refactor must be
**behavior-neutral** and land **one cog at a time**.

## Why

`nebulous_bot/management/commands/runbot.py` (~1,900 lines) defines all 19
commands inline inside `Command.handle()` as closures over nonlocal state
(`server_monitor`, `formatter`, `deployment_time`). Nothing is unit-testable,
every change touches the same file, and dependencies are invisible closure
capture. Cogs make each command group a class with explicit constructor
dependencies.

## Target layout

```
nebulous_bot/cogs/
  __init__.py
  servers.py    !listservers(ls,servers) !openlobbies(open,available) !refresh(update)
  stats.py      !stats(statistics) !mapstats(maps) !serverstats(serverinfo) !graph
  nextgame.py   !nextgame(notify,notifyme,ng) !cancelnextgame(nextgamecancel)
  formation.py  !formation(form,optimize)
  setup.py      !setstatuschannel(setstatus) !setnotificationchannel(setnotifchannel)
                !setnotificationrole(setnotifrole) !removestatus(unsetstatus)
                !showsetup(mysetup,guildconfig)
  admin.py      !restartmonitor(restart) !debugmonitor !status(info)
                !version(v,changelog) !commandlogs(cmdlogs,logs)
```

`runbot.py` shrinks to: bot construction, `setup_command_metrics`, cog
loading, `on_ready` (monitor init + presence), `on_guild_join`,
`on_command_error`, `run_bot()`/SSL. Keep those bot-level.

## Hard requirements (each one has burned us before)

1. **Preserve every decorator exactly**: aliases, `hidden=True`,
   `@commands.is_owner()` on commandlogs, `@commands.has_permissions` +
   `@commands.guild_only()` on setup/admin commands, and the
   `@commands.cooldown` values added in 2.3.4 (listservers/openlobbies
   1/15s channel, refresh 1/30s channel, nextgame 2/30s user, graph 1/15s
   channel, formation 1/30s user).
2. **The eager `formation_optimizer` import must stay on the boot path,
   BEFORE the gateway connects.** Do not let the cog split turn it back
   into a lazy/late import — that caused the 2.3.4 production incident
   (multi-minute GIL-hogging import starving the event loop; see CLAUDE.md
   and review item #12). Safest: keep `from formation_optimizer import ...`
   at module scope of `cogs/formation.py` AND import that module from
   runbot.py at module scope (before `asyncio.run`).
3. **`server_monitor` is None until `on_ready`.** The closures currently
   guard with `if not server_monitor`. Cogs can't capture the nonlocal:
   give each cog a reference to a shared holder (e.g. construct cogs with
   the `bot` and read `bot.server_monitor`, set by `on_ready`), and keep
   the None-guard replies ("monitoring not initialized yet") identical.
4. `_upsert_guild_config` moves into the setup cog; `get_deployment_time`
   into the admin cog (reads `DEPLOYMENT_TIME` env; the bot-start fallback
   timestamp can live on the bot object, set in `on_ready`).
5. `setup_command_metrics` (before/after invoke hooks) and
   `on_command_error` stay bot-level — verify command logging still writes
   CommandLog rows after the split (run a command, check the table).
6. No behavior changes, no output/wording changes, no drive-by refactors.
   Move code verbatim wherever possible.

## Migration order (one cog per commit, verify loop after each)

1. `setup.py` — smallest, stateless besides ORM. Proves the pattern.
2. `stats.py` — pure ORM reads.
3. `servers.py` — needs monitor + formatter.
4. `admin.py` — needs monitor + deployment time.
5. `formation.py` — watch requirement #2.
6. `nextgame.py` — most waiter-state interplay, do last.

After each cog: `.claude/skills/verify/SKILL.md` loop (ruff, pytest bare —
never piped to tail, manage.py check, import smoke test). After the final
cog: bump to 2.5.0 in `Config.VERSION` + `Config.CHANGELOG` + `CHANGELOG.md`
(player-facing wording: internal restructuring, no visible changes), then
deploy per `.claude/skills/release/SKILL.md` and smoke-test in Discord:
`!status`, `!version`, `!listservers`, `!nextgame` + `!cancelnextgame`,
one admin command, and confirm the live status embed still updates.

## New tests to add as cogs land

Command logic becomes testable with a fake monitor (plain object with
`cached_servers`, waiter dicts — see `tests/test_waiter_modes.py` style).
Highest value: nextgame argument parsing (mode tokens incl. `newplayer`,
`-skip`/`--skip`), and the listservers filter-arg parsing currently inlined
in the command body (extract to a pure function during the move — this is
the ONE allowed refactor, it's what makes the split pay off).
